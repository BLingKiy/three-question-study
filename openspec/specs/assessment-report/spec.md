## ADDED Requirements

### Requirement: Assessment report generation
The system SHALL generate an assessment report for a course when all assessment questions for that course have been answered. The report SHALL be generated by AI based on the complete assessment context including all questions, user answers, evaluation results, and follow-up conversation records.

#### Scenario: First report generation
- **WHEN** user taps "查看评测报告" button for a course where all questions are answered and no report exists in DB
- **THEN** system calls AI with the complete assessment context (all questions+answers+follow-ups+knowledge nodes), parses the AI response into structured report data, persists to assessment_reports table, and displays the report

#### Scenario: Subsequent report viewing
- **WHEN** user taps "查看评测报告" button and a report already exists in DB for the course
- **THEN** system loads the report from DB and displays it without calling AI

#### Scenario: Report regeneration on assessment regeneration
- **WHEN** user regenerates assessments for a course (via cycle icon)
- **THEN** system deletes the existing report from assessment_reports table, so next "查看评测报告" tap triggers new AI generation

#### Scenario: Report generation loading state
- **WHEN** AI is generating the report
- **THEN** system displays a loading indicator with text "正在生成评测报告..."

#### Scenario: Report generation failure
- **WHEN** AI report generation fails or returns unparseable content
- **THEN** system displays error message "评测报告生成失败，请重试" and does not persist partial data

#### Scenario: Report generation with API key not configured
- **WHEN** user taps "查看评测报告" and API key is not configured
- **THEN** system displays error message "请先在「我的」页面配置 API 密钥"

### Requirement: Three-dimension ability assessment
The system SHALL assess user ability on three dimensions: Concept Understanding (概念理解), Critical Thinking (批判思维), and Practical Transfer (实践迁移). Each dimension SHALL be scored 0-100 by AI based on the user's overall assessment performance.

#### Scenario: AI dimension scoring
- **WHEN** AI generates the assessment report
- **THEN** AI provides scores for conceptUnderstanding, criticalThinking, and practicalTransfer, each as an integer 0-100

#### Scenario: Dimension analysis text
- **WHEN** AI generates the assessment report
- **THEN** AI provides analysis text for each dimension explaining the user's strengths and weaknesses in that area

### Requirement: Overall review suggestion
The system SHALL include an overall review suggestion in the assessment report, generated by AI based on the user's complete assessment performance.

#### Scenario: Overall suggestion content
- **WHEN** AI generates the assessment report
- **THEN** report includes overallSuggestion text with prioritized review recommendations

### Requirement: Error trace to knowledge node
The system SHALL trace incorrect answers back to specific knowledge graph nodes. Each error trace SHALL include the question ID, the related knowledge node ID and label, and an explanation of the connection.

#### Scenario: Error trace generation
- **WHEN** AI generates the assessment report and there are incorrect answers
- **THEN** AI provides errorTraces array, each element containing questionId, knowledgeNodeId, knowledgeNodeLabel, and traceExplanation

#### Scenario: Error trace with invalid node ID
- **WHEN** AI returns an errorTrace with a knowledgeNodeId that does not exist in the knowledge graph
- **THEN** system skips that error trace entry and does not display it

#### Scenario: Error trace navigation
- **WHEN** user taps on an error trace item in the report
- **THEN** system navigates to LearningSpacePage with the knowledgeNodeId as a route parameter, highlighting the corresponding node in the knowledge graph

#### Scenario: No incorrect answers
- **WHEN** all questions are answered correctly
- **THEN** errorTraces array is empty and the report displays "全部回答正确，无需溯源复习"

### Requirement: Assessment report data persistence
The system SHALL persist assessment report data in RDB with an `assessment_reports` table.

#### Scenario: Report table schema
- **WHEN** the app initializes the database
- **THEN** system creates `assessment_reports` table with columns: id (TEXT PRIMARY KEY), course_id (TEXT NOT NULL, UNIQUE), dimensions_json (TEXT NOT NULL), overall_suggestion (TEXT NOT NULL), error_traces_json (TEXT NOT NULL), dimension_analysis_json (TEXT NOT NULL), created_at (INTEGER NOT NULL)

#### Scenario: Save report
- **WHEN** AI report generation completes successfully
- **THEN** system inserts a record into assessment_reports table with the parsed report data

#### Scenario: Load report
- **WHEN** user views a report that already exists
- **THEN** system queries assessment_reports by course_id and returns the report data

#### Scenario: Delete report on course deletion
- **WHEN** a course is deleted
- **THEN** system deletes the corresponding report from assessment_reports table

### Requirement: Three-dimension radar chart
The system SHALL display a three-dimension radar chart using ArkWeb+ECharts showing the three ability dimensions (概念理解, 批判思维, 实践迁移) with their scores.

#### Scenario: Radar chart display
- **WHEN** user views the assessment report
- **THEN** system displays a radar chart with three axes labeled "概念理解", "批判思维", "实践迁移", each axis scaled 0-100, with the user's scores plotted

#### Scenario: Radar chart ArkWeb implementation
- **WHEN** radar chart component is rendered
- **THEN** system uses ArkWeb component with ECharts library loaded from rawfile, communicates scores via javaScriptProxy

### Requirement: View report button availability
The system SHALL display a "查看评测报告" button on each answered assessment question and in the course question list. The button SHALL be disabled (grayed out) until all questions for the course have been answered, then enabled.

#### Scenario: Button shown on answered question
- **WHEN** user has submitted an answer for a question
- **THEN** a "查看评测报告" button is displayed below the answer result area

#### Scenario: Button disabled when questions remain
- **WHEN** not all questions for the course have been answered
- **THEN** the "查看评测报告" button is displayed but disabled (grayed out, non-interactive)

#### Scenario: Button enabled when all answered
- **WHEN** all questions for the course have been answered
- **THEN** the "查看评测报告" button is enabled and tappable

#### Scenario: Button in course question list
- **WHEN** user views the course group in assessment center with answered questions
- **THEN** each answered question card shows a "查看报告" button, disabled until all course questions answered

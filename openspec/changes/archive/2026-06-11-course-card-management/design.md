## Context

当前课程卡片仅有删除按钮（底部圆形图标），CourseManager 已实现 `archiveCourse()`/`completeCourse()`/`updateCourseStatus()` 方法但 UI 未暴露。课程列表按 `updated_at` 降序排列，无排序切换。已归档课程(status='archived')仍正常显示在列表中，无法区分。

## Goals / Non-Goals

**Goals:**
- 课程卡片添加操作菜单，支持归档/取消归档、标记完成/取消完成、删除（带确认）
- 已归档课程默认隐藏，底部折叠区域"已归档课程(N)"可展开查看
- 排序切换：按最近使用时间、创建时间、学习进度三种排序方式
- 归档课程卡片视觉置灰

**Non-Goals:**
- 不实现拖拽排序
- 不实现课程分享/导出
- 不实现课程重命名

## Decisions

### 1. 操作菜单使用 bindMenu 而非长按

**决策**：在课程卡片右上角添加"更多"按钮（三点图标），点击弹出 `bindMenu` 菜单。

**理由**：ArkUI 的 `bindMenu` 是标准菜单组件，交互一致性好。长按手势在移动端容易误触，且与列表滚动冲突。

**替代方案**：长按弹出菜单 → 拒绝，易误触。

### 2. 已归档课程折叠区域

**决策**：在课程列表底部添加"已归档课程(N)"折叠区域，默认折叠，点击展开显示归档课程。

**理由**：归档课程不常查看，折叠显示保持主界面简洁。与测评中心的课程分组展开/折叠交互一致。

### 3. 排序切换放在搜索栏旁

**决策**：在搜索栏右侧添加排序图标按钮，点击弹出排序选项（最近使用时间/创建时间/学习进度）。

**理由**：排序与搜索是同维度的列表控制功能，放在一起最直观。

### 4. 删除增加 AlertDialog 确认

**决策**：删除操作从直接执行改为先弹出 AlertDialog 确认。

**理由**：删除是破坏性操作，且级联删除大量数据，必须有确认步骤防止误删。

## Risks / Trade-offs

- **[归档课程数据残留]** 归档不删除数据，课程多了可能占用存储 → 可接受，用户可手动删除归档课程
- **[排序性能]** 按进度排序需要为每个课程查询进度 → 进度已在 loadCourses 时预计算到 courseProgressMap，无需额外查询

## Context

当前测评中心（AssessmentCenterPage）已实现基础答题流程：按课程分组展示测评、单选/多选/判断/主观四种题型、客观题本地判题、主观题AI评价、结果报告+雷达图。但存在以下问题：

1. **生成入口缺失**：测评中心没有"生成测评"按钮，用户必须从学习空间触发Q3
2. **上下文不完整**：executeQuestion3 只传入知识图谱节点，未传入用户上传材料内容和争议数据
3. **维度/类型不明示**：题目列表中不显示布鲁姆层级和题型标签
4. **无追问环节**：答完题后直接进入下一题或结果报告，缺少追问深化学习的机会
5. **追问数据无持久化**：没有追问记录的存储和回看

## Goals / Non-Goals

**Goals:**
- 测评中心按课程分组，每个课程旁有"生成测评"按钮，初始无题目
- 生成测评时融合完整资料库上下文（知识图谱+争议数据+用户上传材料内容+WebSearch资料）
- 每道题明示布鲁姆认知维度和题型
- 答题后进入追问模块，用户可追问，AI基于题目+答案上下文深入解答
- 追问记录持久化，可回看历史追问对话
- 客观题判题后显示正确答案解析

**Non-Goals:**
- 不实现多用户协作答题
- 不实现测评题目编辑/删除
- 不实现题目收藏/标记功能
- 不实现错题本独立页面（错题在结果报告中展示即可）
- 不实现限时答题

## Decisions

### 1. 测评生成按钮放在课程卡片旁

**决策**：在测评中心每个课程分组标题栏右侧放置"生成测评"按钮，而非在课程卡片上。

**理由**：测评中心已按课程分组，按钮放在分组标题旁最直观。避免在课程卡片上增加更多操作按钮导致拥挤。

**替代方案**：在课程卡片底部添加按钮 → 拒绝，因为卡片已有进度信息，再加按钮会过于拥挤。

### 2. 追问模块作为答题后的内嵌区域

**决策**：每道题答完后，在题目下方展开追问输入区域（类似讨论区的消息列表+输入框），不跳转新页面。

**理由**：追问是答题的延伸，保持同一页面上下文连贯。用户可随时点"下一题"跳过追问。

**替代方案**：跳转到独立追问页面 → 拒绝，会打断答题流程，增加导航复杂度。

### 3. 追问数据模型：assessment_follow_ups 表

**决策**：新建 `assessment_follow_ups` 表，字段：id, assessment_id, role(user/assistant), content, created_at。

**理由**：追问是测评的子资源，与 assessment 一对多关系。role 字段区分用户提问和AI回复，类似 discussion_message 的设计模式，保持一致性。

**替代方案**：复用 discussion_message 表 → 拒绝，讨论区是争议点的讨论，与测评追问语义不同，混用会导致查询复杂。

### 4. 生成测评时收集完整资料库上下文

**决策**：executeQuestion3 新增 `materialsContent` 参数，调用前收集：用户上传txt/md文件内容 + 知识图谱节点JSON + 争议节点JSON + WebSearch资料标题/URL。

**理由**：需求要求"基于用户上传文件和已生成的全部课程资料库"生成题目，当前只传知识图谱节点不够完整。

### 5. 追问AI Prompt 设计

**决策**：追问prompt包含：原题目、用户答案、判题结果/评价结果、追问历史、当前追问问题。AI角色为"学习导师"，基于题目上下文深入解答。

**理由**：追问需要理解用户当前的认知水平（从答案和判题结果推断），才能给出有针对性的深入讲解。

### 6. 维度/类型标签UI

**决策**：在题目卡片上使用小标签（Tag/Chip）显示布鲁姆层级（如"记忆""理解"）和题型（如"单选""主观"），使用不同颜色区分。

**理由**：标签是最直观的信息展示方式，不占用太多空间，用户一眼可见题目属性。

## Risks / Trade-offs

- **[AI生成耗时]** 生成测评和追问回复都需要调用AI，可能耗时较长 → 显示加载动画，生成按钮置灰防重复点击
- **[材料内容过长]** 用户上传大量材料可能导致prompt超长 → 截取前8000字符，超出部分省略并提示
- **[追问token消耗]** 每次追问都调用AI，频繁追问可能消耗大量token → 追问无次数限制，但每次追问显示"思考中"加载状态
- **[RDB表增加]** 新增 assessment_follow_ups 表 → 在 RDBService.initialize 中 CREATE TABLE IF NOT EXISTS，兼容旧版本
